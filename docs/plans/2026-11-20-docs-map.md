# The docs site publishes exactly the map's pages

## At a glance

The human, 2026-11-20 10:0x, of the docs map drawn that morning (the orchestrator branch's
`worktrees/mocks/2026-11-20-docs-map/map.md`): "the map is perfect starting
point, and on your question, yes publish exactly the map's pages". The map is the page a partner
opens first: a branch for everyone and one per kind of partner, sixteen pages that exist and three
marked "not yet written". This piece moves it onto `main` as the site's first page and the one list
its build reads: a page not on the map is not published, and a map line with no page stops the
build.

The cheapest safe path keeps everything the site already has: the same Docusaurus config, the same
link rewrite for a file the site leaves out (`site/links.ts#L42-L45`), the same workflow. Only where
the list of pages comes from changes: from eight globs to the map. About 34 minutes of build, then
one look.

## The slice

One slice: the map committed at its home, the site built from it with its sidebar drawn from it,
the two refusals in the build, the pages that describe the site made true, and the human's look at
the built site on their machine. Walkable when it ends: the build serves the map at the site's root
and the sixteen pages under it, nothing else.

Not in this slice, and not blocked by it (the piece's later slices): a tag for each docs release, a
script that lists the pages added or changed between two tags, an agent's check of each one at a
release, and an index for agents that is never published. What keeps them open is named under
"What the later slices need from this one".

## How the site decides what it publishes today

By globs, not by the sidebar. `site/docusaurus.config.ts#L7-L16` lists eight include patterns
(`README.md`, `docs/*.md`, `docs/conventions/*.md`, `docs/memo/*.md`, `docs/partners/**/*.md`,
`ops/README.md`, `services/*/README.md`, `services/*/docs/**/*.md`), and the one docs plugin
publishes every file they match (`#L46`). The sidebar (`site/sidebars.ts`) only orders them and
labels them; a page off the sidebar would still be published, without a sidebar of its own. The
same list goes to the link rewrite (`#L49`): a link to a file the list leaves out becomes a GitHub
link at the built commit, so it opens rather than breaking the build (`onBrokenLinks: 'throw'`,
`#L27`).

Today the globs match 39 tracked pages. Sixteen are on the map; the other 23 leave the site: the
root `README.md`, `docs/README.md`, `docs/activity-log.md`, `docs/architecture-detail.md`,
`docs/decisions.md`, `docs/open-items.md`, two conventions (collaboration, documentation), the
seven memos under `docs/memo/`, and the eight service pages.

## Decided here

- **The map's home is `docs/partners/map.md`.** `site/CLAUDE.md#L12-L13` says every page lives
  once where it sits and a new page for partners goes in `docs/partners/`; the map is that page.
  It becomes one of the living documents the citation test reads, by its existing pattern
  (`scripts/src/citations.ts#L27`).
- **The map is the site's root, by its front matter `slug: /`**, Docusaurus's own way to give a
  docs-only site its home page. Needed, not chosen: the root `README.md` serves `/` today, and it
  leaves, while `.github/workflows/docs.yml#L83` fails a build with no `site/build/index.html`.
  GitHub shows the key as a one-row table above the map; no other site detail enters a page.
- **Each map line names its page by a link on the page's name**, in place of the mock's grey
  `main: <path>` after it. A partner clicks the name on the site; a keeper reads the path on GitHub;
  the build reads the same link. The mock's sentence on the grey text (its `#L8-L9`) becomes "A
  page's name opens it." The mock's "Notes for the human" stay in the mock: its question is
  answered, and the rewrites it names are the next slices' work on the board.
- **The three "not yet written" lines stay on the map and publish nothing.** No stub page: a page
  with nothing in it would be published as if it answered. The line keeps its words and its
  marker, carries no link, and has no sidebar entry, since an entry is a door. When a page is
  written, its line gains the link in the same commit, which is what a later release check reads as
  an added page.
- **The map is read by one module, `site/map.ts`**, which takes the map's text, not its file, so a
  later script can read the map at any tag. It gives three things: the pages (the config's include
  and the link rewrite's list, the map itself first), the sidebar (the map first, then a category
  per branch, each page under its map name), and the refusals below.
- **Two refusals, both in the build, so `docs.yml` runs them on a push that changes only the map.**
  The site's CI check in `ci.yml#L508` runs only when a push also touches a path `ci.yml` names
  (open item 605), while `docs.yml` builds on any change under `docs/**`. First, reading the map:
  a line whose linked file does not exist, a line under "The map" that is neither a branch, a page
  nor a promised page, a link that is not a whole `.md` page, and a page named twice: each stops
  the build, naming the map's line. Second, once Docusaurus has loaded every page: a small plugin
  in the config, in Docusaurus 3.10's `allContentLoaded`, compares every loaded doc's `source` with
  the map and stops the build on a page not on the map, a map page with no loaded doc, or a map
  whose address is not `/`. The second refusal does not trust that the include came from the map: a
  glob added back, a second docs plugin or a page given by any other way is red by name.
- **The refusals are held by unit tests, and the build stays the end-to-end test.** A refusal held
  only by a mutation once is not held after it, since the committed map never trips it. The site
  gains vitest, its config copied from `shared/vitest.config.ts` as `site/vitest.config.mts` (the
  site package is not an ES module, commit `cdb5adf9`), coverage 100 % of `site/map.ts`, the
  other three source files excluded as `elsewhere: the site's build runs them`. Its test script becomes
  `vitest run --coverage && docusaurus build` (`site/package.json#L9`).
- **`docs.yml`'s `paths:` stay as they are** (`#L10-L23`). They now name more than the site shows
  (the root README, the services), which costs a spare build on such a push; a list narrowed to the
  map would silently miss a page the map adds later.
- **`site/links.ts` is not changed**, only given the map's list in place of the globs, so open item
  606's trigger (the next change to `links.ts`) is not met.

## What the later slices need from this one

- **A tag a release:** the map is read from its text, so a script reads it at any tag with `git
  show <tag>:docs/partners/map.md` and gets the same pages the build published then.
- **The changed pages between two tags:** the pages of the map at each tag, and `git diff
  --name-only` between them, restricted to those pages; the map's own change counts as a change.
- **The agent's check:** each page line keeps its words for whom it is and what it answers, and its
  line number, so a check can hand a page and its promise over together.
- **The agents' index:** a memo kept off the map is not published, by the same build, wherever it
  sits.
