# One place for each decision

## At a glance

Five decisions in this code base are written out by hand in three to eleven places, and nothing
fails when a copy is missed: the retry bound, "list under a prefix and refuse a short answer", the
three screen widths, the eleven environment names, and what a 403 means. This piece gives each one
home and makes every former copy import it. Nothing a user sees changes — that is the point, so
there is no look and no picture run. The cheapest path is reuse, not design: three of the five
already have a general version in the tree (`bff/src/orders.ts#L66`, `ui/src/page.ts#L25`,
`shared/src/c-storage.ts`), so those are moves and import lines rather than new machinery. Two of
the five can be made **code-held** — a wrong or missing copy becomes a typecheck error — and three
stay reader-held, which this plan says per shape rather than once. **It asks the human nothing.**

## The slice

One slice: five shapes, each a one-home declaration plus its importers plus a mutation that proves
the copies are really gone, then one whole-tree gate and the recap. It is walkable at every step,
because no behaviour moves: the app does the same thing after each step and its tests say so.

The constraint that decides this piece's order **outside** itself, and it must not be lost: five of
the back-end files here — `bff/src/staff.ts`, `orders.ts`, `clients.ts`, `lists.ts`,
`staff-records.ts` — are the same five the later activity-log piece must touch (its cost is 28 write
sites that do not know who is acting). **This piece and the activity log are sequenced, never
parallel**, or those five files collide at the merge. Doing this one first should shrink that 28,
since collapsing four copies of a write pattern into one place is what reduces a count of places.

**Two of the five reach the stronger form the convention asks for** — a one home the working code
cannot bypass — and both by the type system, not by a text check: in 3 the width type is *derived*
from the one home, so a width that is not in it is a typecheck error at every call site; in 4 the
names are *keys* of the one home, so a misspelling in a spec cannot compile. **Three stay
reader-held** (1, 2, 5): the mutation above proves every present copy is wired, but nothing stops a
*sixth* copy being written tomorrow. Shapes 1 and 5 have no list for the working code to append to —
a bound and a predicate are values, not sets. Shape 2 could be made code-held by removing
`listRecords` from the client the route modules are handed, so an inline copy would not compile;
that is a wider change than this piece, and it is named here as the next step rather than taken.

## The order, and what is independent

Three lanes, and the file they share is what sequences each:

- **Shapes 1 and 3 share nothing, but shapes 1 and 2 both edit `bff/src/orders.ts`** (`#L48` and
  `#L57-L66`), so they are sequenced: 1 then 3 in the step list above.
- **Shapes 3 and 4 both append a line to `shared/src/index.ts`**, so they are sequenced too: 4 then
  5 in the step list.
- **Shape 5 (the 403) touches only `ui/src` screens and shares no file with any other shape**, so it
  is genuinely independent and could run in parallel with the back end if the orchestrator wanted
  two agents.

**The gate per shape is the touched packages', not the tree's**, which is why each step's done-when
names its own `--filter` commands: steps 1 and 3 are `shared` + `bff`, step 2 is `ui`, step 4 is
`shared` + `ui` + `visual` + `walk`, step 5 is `shared` + `scripts` + `walk`. **The whole-tree
`pnpm check` at the end is needed and not optional**: knip and prettier run tree-wide, not per
package, and three of the five shapes add a `shared` export that knip will call unused if any
importer was missed. `make check` in `c-storage/` is **not** needed: no Go file changes, and the
registration at `c-storage/internal/server/server.go#L51-L54` is read as the model only.

**The collision with milestone B3, the UI's shape:** B3 touches `ui/src` as shape 5 does, and they
are the pair most likely to collide. **B3 opens only after this piece merges**, the same rule the
activity log gets, and this piece is two hours. If B3 must start sooner, shape 5 is step 2 on
purpose and its commit is cherry-pickable alone: one new helper in `page.ts` and one changed line in
each of six screens, which is the smallest diff a rebase can be asked to carry.
