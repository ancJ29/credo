# The tab icon and the phone app: each company's icons, its phone-app description at an address naming it, the browser's bar in its colour

## At a glance

What it is for: the branding campaign's last milestone. The root, or anyone given the settings
right, uploads a tab icon and a phone-app icon; the company's people see the icon in the tab and, on
a phone, add the app to the home screen under the company's name and icon, opening full screen at its
sign-in, the bar in the header's colour. A company with no icon gets one drawn from its colour and
first letter. The cheapest path: two more kinds on milestone 3's picture record and route; each size
made in the browser at the choice, as a photo is shrunk; the BFF draws the stand-in and writes the
phone-app description (the manifest) from the settings; React draws the head. The price: 139 machine
minutes of code in seven steps, then 62 waiting for your word (the walk, your run, the landing), three
looks.

## The slice

One slice: the root opens Settings, uploads a tab icon and a phone-app icon; each saves at its
choice, and the preview's tab and home-screen tile wear them; the browser's tab shows the icon; on a
phone, "Add to Home Screen" names the company, shows its icon and opens at its sign-in, full screen,
the bar in the header's colour. Removing an icon brings back the drawn one. Stage 1 is the gallery and
the fake (steps 3, 6); stage 2, the gates and the whole check; stage 3, the gallery look and the walks
page; stage 4, ridge, your iPhone in Safari. **Not in it:** the iPhone's start-up pictures and an
Android maskable icon (the first left out by the campaign, `flow.md`'s "What stays out", the second not asked); item 693, the
walk's tab and language check, whose trigger is milestone 3's run of `piece-1`, the first.

## What the code holds

**1. The head today.** `ui/index.html#L3-L7`: a charset, a viewport and `<title>Credo</title>`; no
icon, no manifest, no theme colour. Code draws the title in both branches (`ui/src/ClientApp.tsx#L221`,
`#L339`) and the language through `Providers`. A company's people get the browser's blank tab icon;
on a phone, nothing names the app or its icon, and an added page opens in a browser tab. The front
door serves every dotted path from the one shared bucket (`ops/test.sh#L333`, `#L340`), so a
per-company icon is a BFF address under `/api/`, which CloudFront passes on with the door's key
(`ops/env.yml#L774-L786`, `bff/src/server.ts#L54-L59`) and never caches.

**2. The record and the route: milestone 3's, two more kinds.** Milestone 3 (piece 250.3, planned
at `39e1b49e`, unlanded) keeps each picture as `tenant.<id>.picture.<kind>`, `{ picture }`, served at
`/api/pictures/<code>/<kind>?v=<tag>` with no sign-in, `nosniff`, a sandboxing policy, a year's cache
at the record's tag, base64 for `image/…` on Lambda, and saved by `PUT /api/pictures/<kind>` under the
settings right. This piece adds, in its one list of kinds in `shared`:

- **`tab-icon`**: one PNG, 64 pixels square.
- **`app-icon`**: one PNG, 512 square, and `small`, the same at 192, in the one record, so one choice
  is one save (milestone 3's choice 3 refuses a press saving three records). `?size=192` serves `small`.
- **The save checks** the type (`image/png` alone for these kinds), each picture within 200 KB
  (`shared/src/config.ts#L45`, decision 5), and the sides read from the PNG's header, refusing any other.
- **None stored** answers the drawn icon (4 below), `no-cache`. The settings reply's `pictures`
  (milestone 3) then names, for these two kinds, the drawn address at the settings' version, so the
  UI always has one.

Milestone 3's files this piece touches: its kinds list and stored picture in `shared`; its route and
`pictures.route.test.ts` in `bff`; its `PictureField` and the settings page's Pictures block; `Brand`
(`ui/src/brand.ts#L4`); the fake's pictures. Every step on them follows its landing.

**3. The sizes, made in the browser.** Chrome installs an app whose manifest has "a 192px and a 512px
icon" (web.dev, "What does it take to be installable?"); an iPhone takes the `apple-touch-icon` link,
"an icon file in PNG format", and where none fits its size "the smallest icon larger than the
recommended size is used" (Apple, "Configuring Web Applications"): the 192 serves it. The app already
shrinks pictures in the browser on a canvas, a person's photo to its middle square
(`ui/src/photo.ts#L14-L37`) and a delivery's photo (`#L44-L56`), untested in jsdom and held by the walk.
`ui/src/icons.ts` copies that: the middle square; a tab icon of any image within 200 KB made 64; a
phone-app icon refused under 512 on its shorter side, then made 512 and 192, **each drawn on white**,
since an iPhone fills a transparent part black (legacy
`workspace/uis/c-mngt/docs/memo/client-branding.md#L152`). The BFF has no image library
(`bff/package.json#L27-L32`) and needs none: it checks and serves bytes.

**4. The drawn icon** (decision 6). A square of the company's colour, its first letter in white: the
plain name's first, its marks dropped (`Ă` gives `A`), `Đ` kept, else the code's first. An iPhone takes
only a PNG, so it is drawn as pixels, not SVG: `shared/src/icons.ts` holds a monoline letter for each
of A to Z, Đ and 0 to 9 as strokes on a grid, a rasteriser that shades each pixel by its distance to
the nearest stroke, and a PNG writer (its chunks, a CRC, the deflate passed in: zlib's in the BFF, a
stored one in the fake, so both draw the same pixels). No font file, no dependency.

**5. The manifest** (decision 3). `GET /api/manifest/<code>`, through the front door, no sign-in, no
company header: the code resolves as milestone 3's route does (404 unknown, 503 a closed box). Who
may fetch it: anyone, as the settings' GET already answers the same name, colour and description to
anyone naming the code (`bff/src/app.ts#L332-L336`). `application/manifest+json`, `no-cache`. Built by
one function in `shared` from the settings and the icons' addresses:

| Field | Value |
| --- | --- |
| `name`, `short_name` | the plain name (point 4 of the campaign: no "Credo") |
| `description` | milestone 2's description, left out when empty |
| `start_url` | `clientLinkPath(code)`, `/login?client-code=<code>` (`shared/src/wire.ts#L196`): the address names the company, so an added app opens on it whatever the device kept; signed in, `/login` opens the first page (`ui/src/ClientApp.tsx#L492`) |

Safari uses manifest icons only "when there is no `apple-touch-icon`" and for `purpose` any or
unset (WebKit, "New WebKit Features in Safari 15.4"); the link wins, so both name the same picture.
